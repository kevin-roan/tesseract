Tesseract on macOS: the container VM

How we got server containers, public URLs and the sandbox running end to end on an M1 Mac mini (2021, 8 GB RAM, 512 GB disk), what we built, and every problem we hit on the way.

Overview

Tesseract's server containers need Sysbox, a container runtime that only runs on Linux. Docker Desktop on macOS can't run it, so on the Mac the containers page showed ✗ Sysbox runtime: Install Sysbox and nothing could be created.

The fix: on macOS, Tesseract now manages one dedicated Linux VM (Colima, profile tesseract) with Sysbox installed inside it. The sandbox and the server containers both run in that VM. Docker Desktop is no longer used.

1. Why a VM, and why not Docker-in-Docker

Server containers are full Linux machines: systemd as PID 1, their own Docker daemon, Tailscale SSH. Sysbox makes that possible without giving the container root on the host. Options we weighed:

OptionVerdict
Privileged Docker-in-Docker on Docker DesktopRejected. --privileged is root on Docker Desktop's VM, which shares /Users, so a compromised container could reach the Mac's files. It also breaks ADR 0011's no-privileged rule, and it would mean two code paths.
A second VM next to Docker DesktopRejected: two VMs don't fit in 8 GB.
Apple's container toolRejected for now: it isn't Docker (so a second backend), and it's unproven with systemd plus a nested dockerd.
One Colima VM with Sysbox, replacing Docker DesktopChosen. The same code path as Linux: only the Docker endpoint differs.

The decision is recorded in docs/adr/0012-macos-container-vm.md. ADR 0011 now points to it instead of saying "Linux hosts only".

2. Colima vs Docker Desktop

Both run a Linux VM with the Docker engine; the docker command on the Mac talks to it. For Tesseract, Colima replaces Docker Desktop completely.

How Sysbox gets into the VM

A provision script in colima.yaml runs on every VM boot. It:

  • repairs DNS first: if /etc/resolv.conf has no nameserver, it writes 1.1.1.1 and 8.8.8.8;
  • exits early if Sysbox is installed and both services are active;
  • otherwise waits for DNS (switching to public DNS after 30 s), downloads the pinned sysbox-ce 0.7.1 .deb, verifies its sha256, installs it, and enables sysbox-mgr and sysbox-fs.

Lima ignores provision failures and colima start still exits 0, so the app doesn't trust that: it checks that the runtime is registered and both services are active, and re-runs the script over colima ssh if not.

4. Fitting in 8 GB

The VM's memory is fixed at 5 GB and isn't returned to macOS while it runs. Inside the VM, Docker's --memory is a ceiling, not a reservation, so the sandbox and server containers share the 5 GB.

  • One heavy job at a time: stop server containers before Android builds (tesseract containers stop <name>).
  • --restart unless-stopped remembers a manual stop, so stopped containers stay stopped across restarts.
  • New server containers on macOS get --memory 1024 unless you pass --memory.
  • colima stop tesseract gives all of the VM's memory back to macOS.
  • Don't run Docker Desktop or any other Colima VM next to it (we found a leftover default VM using 2 GB).

5. What was built

App: core

  • src/core/vm/ (new): vmStatus, setupVm, startVm, stopVm. It installs the tools with Homebrew, adds Homebrew's plugin folder to ~/.docker/config.json (dropping Docker Desktop's credsStore), writes colima.yaml, starts the VM (force-stopping a broken one), creates the Docker context if it's missing, switches to it, and waits for Sysbox.
  • Docker detection: on macOS a colima-<profile> context counts as Colima, and its start command is colima start <profile>. A compose that reports no version number (Homebrew's 5.0.0 said "dev") is now a warning, not a block.
  • Containers: on macOS the Sysbox check offers Set up VM (setup-vm); new containers default to 1 GB; waiting for systemd now retries while its bus isn't up yet.

App: UI and CLI

  • Onboarding on macOS lists Tesseract VM (recommended) first; Docker Desktop is labelled "Can't run server containers on macOS".
  • Preferences → Containers: Set up VM button with progress and cancel; the create dialog explains when the VM is missing.
  • New CLI: tesseract vm status|setup|start|stop. tesseract containers doctor points at tesseract vm setup on macOS.

Script and docs

  • scripts/setup-mac.sh: one command for the whole Mac setup (see section 8). A test keeps its embedded colima.yaml identical to the app's generator.
  • Docs: ADR 0012 (new), ADR 0011, the blueprint, the server-containers runbook (macOS section, one-command section, troubleshooting), architecture and security notes, onboarding docs.

6. How it was verified

  • Unit tests: typecheck clean for all workspaces; Electron suite 280 files, 1783 tests passing.
  • Live test on Linux: real Colima 0.10.3 and Lima 2.2.1, with the generated config (QEMU in place of macOS's VM engine), isolated from the dev machine's own Docker. Results: the real server image built; a container under sysbox-runc with a 1 GiB limit booted systemd with no failed units; nested docker run hello-world worked; Docker 29 with the containerd image store works with Sysbox 0.7.1.
  • Code review of the whole diff, focused on Linux regressions.
  • On the Mac mini: Sysbox active, test container under sysbox-runc ran, server image built, sandbox built and joined the tailnet.

Commands used to unblock by hand

# 4. recreate the Docker context
docker context create colima-tesseract --docker "host=unix://$HOME/.colima/tesseract/docker.sock"

# 5. give the VM DNS
colima ssh -p tesseract -- sudo sh -c 'rm -f /etc/resolv.conf && printf "nameserver 1.1.1.1\nnameserver 8.8.8.8\n" > /etc/resolv.conf'

# 6. compose that reports a real version
brew upgrade docker-compose

# 7. drop Docker Desktop's credential helper
cp ~/.docker/config.json ~/.docker/config.json.bak
jq 'del(.credsStore)' ~/.docker/config.json.bak > ~/.docker/config.json

# 9. sandbox Tailscale auth key from a file
ENV="$HOME/Library/Application Support/Tesseract/sandbox/.env"; KEY="$(tr -d '\r\n' < ~/ts-key.txt)"; case "$KEY" in tskey-auth-*) grep -q '^TS_AUTHKEY=' "$ENV" && sed -i '' "s|^TS_AUTHKEY=.*|TS_AUTHKEY=${KEY}|" "$ENV" || printf 'TS_AUTHKEY=%s\n' "$KEY" >> "$ENV"; unset KEY; tesseract sandbox up && tesseract sandbox pair ;; *) unset KEY; echo "ts-key.txt doesn't hold a tskey-auth- key" ;; esac

8. Setting up a Mac (the script)

./scripts/setup-mac.sh                       # everything, asks before quitting Docker Desktop
./scripts/setup-mac.sh --skip-sandbox        # VM + server containers only
./scripts/setup-mac.sh --skip-containers     # VM + sandbox only
TAILSCALE_KEY_FILE=~/ts-server-key.txt CLOUDFLARE_TOKEN_FILE=~/cf-token.txt ./scripts/setup-mac.sh
  1. Checks the Mac: macOS 13+, not run as root, at least 20 GB free, finds Tesseract (app or repo checkout).
  2. Installs Homebrew if missing, then colima docker docker-compose docker-buildx jq.
  3. Adds Homebrew's plugin folder to ~/.docker/config.json, drops credsStore: "desktop", upgrades compose if it reports no version.
  4. Quits Docker Desktop (asks first) and turns off its login start.
  5. Writes ~/.colima/tesseract/colima.yaml (backs up and asks before replacing your own edits).
  6. Starts the VM (restarting it if the config changed or it's broken), creates and switches to the colima-tesseract context.
  7. Checks Sysbox; re-runs the provision script if needed; runs a test container under sysbox-runc.
  8. Sandbox: tesseract sandbox build, then shows the pairing QR code.
  9. Server containers: saves the Tailscale key and Cloudflare token (hidden prompts or files), tesseract containers build, doctor.
Safe to re-run: finished steps are skipped. Everything is logged to ~/Library/Logs/tesseract-setup-mac.log.
Two different Tailscale keys: the sandbox key (reusable off, ephemeral off, pre-approved, tag tag:tesseract) goes in the sandbox .env; the server containers key (reusable, pre-approved, tag tag:tesseract-server) goes to tesseract containers tailscale-key.

9. Daily use

tesseract vm status                    # state, context, Sysbox, size (new builds)
colima list                            # all Colima VMs; only "tesseract" should run
tesseract containers ls
tesseract containers stop <name>       # before Android builds
tesseract containers start <name>
colima stop tesseract                  # free all of the VM's memory
colima start tesseract

10. Testing a public URL

Serve a page on port 80 inside a server container and publish it as test.kevinroan.com.

  1. Connect Cloudflare and check the zone: 
    tesseract domains login < /path/to/cloudflare-token.txt
tesseract domains zones        # kevinroan.com must be listed
  2. Create the container and open a shell: 
    tesseract containers create test
tesseract containers ssh test
  3. Inside it, serve a page on 0.0.0.0:80 (Cloudflare's tunnel can't reach 127.0.0.1): 
    mkdir -p /root/site && echo '<h1>Hello from test on the Mac mini</h1>' > /root/site/index.html
docker run -d --name web --restart unless-stopped -p 80:80 -v /root/site:/usr/share/nginx/html:ro nginx:alpine
curl -s localhost
exit
  4. Publish and test (allow a minute for DNS): 
    tesseract domains add test.kevinroan.com test 80
tesseract domains ls
curl -s https://test.kevinroan.com
  5. Clean up: 
    tesseract domains rm test.kevinroan.com
tesseract containers rm test --yes

The Cloudflare token needs Zone · DNS · Edit, Account · Cloudflare Tunnel · Edit and Zone · Zone · Read, created at dash.cloudflare.com/profile/api-tokens.
