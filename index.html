Tesseract — Setup Guide

A phone-controlled, sandboxed development machine. The Expo app talks over Tailscale to a controller inside a Docker sandbox that has a virtual display (VNC), wine, Electron/Android/Node tooling and Claude Code. You can build, run and visually test apps (including Windows Electron builds through wine) from your phone.

Overview

Time needed: about an hour the first time, mostly the first image build (~5 GB).

2. Prepare Tailscale

  1. In the admin console → DNS: turn MagicDNS on and enable HTTPS certificates. Note your tailnet name (e.g. tail1234.ts.net).
  2. In the Access controls editor, add a tag and a grant (adjust src): 
    "tagOwners": { "tag:tesseract": ["autogroup:admin"] },
"grants": [
  { "src": ["autogroup:member"], "dst": ["tag:tesseract"], "ip": ["tcp:443", "tcp:5901"] }
]
  3. Settings → Keys → Generate auth key: reusable off, ephemeral off, pre-approved on, tags tag:tesseract. Copy the tskey-auth-… value.
The auth key is only used on first start. The node state is then kept in the tesseract-tailscale volume and you can remove the key from .env. Host Tailscale is never touched.

git clone <this repository> tesseract

Every variable is documented inline in infra/compose/.env.example.

.env holds secrets (auth key, tokens). It is git-ignored; keep it 0600. bun run sandbox config prints them too — never paste its output.

5. Build and start the sandbox

bun run sandbox config > /dev/null && echo config ok   # validate .env + mode
bun run sandbox up --build     # builds tesseract/sandbox:latest, starts the stack
bun run sandbox status         # containers + controller status
bun run sandbox doctor         # display, VNC, controller, wine, Android, disk checks

Right after up, doctor may say the controller is still starting — run it again a few seconds later. A WARN for Claude auth is normal until you log in (step 9).

Check from any device on the tailnet:

bun run sandbox logs tailscale -f
curl -fsS https://tesseract-sandbox.tail1234.ts.net/v1/health
# {"ok":true,"version":"0.1.0","protocolVersion":1,"sandboxId":"tesseract-sandbox"}
Want to try everything first without Tailscale? Run bun run e2e: it builds the image, starts an isolated loopback-only stack, runs the full end-to-end suite and tears it down (3–5 min on a warm cache).

6. Pair the phone

bun run sandbox pair

Prints a tesseract://pair?url=…&token=…&name=… link and a QR code. The token is a secret — anyone with it controls the sandbox (within the tailnet).

On the phone: Tailscale connected → Tesseract → Agents tab → Pair a sandbox → scan the QR code (or enter URL + token manually). Opening a tesseract://pair link pre-fills the form; you still tap Pair sandbox.

7. Run the mobile app (development build)

cd apps/mobile
bun run android            # expo run:android — builds & installs the dev client
# or: bun run ios          (macOS + Xcode)
# or: eas build --profile development
cd ../..
bun run mobile             # Metro for the dev client

The Agents tab becomes the sandbox hub: connection state, CPU / memory / disk, display, quick actions (Display, Terminal, Claude, Build), projects, processes, terminal sessions, builds and Claude runs.

Release builds block plain http:// (Android cleartext, iOS ATS). The default tailscale mode uses HTTPS and works; local / host-tailscale modes over HTTP only work in dev builds unless you add a cleartext exception.

8. First build: Electron for Linux and Windows (wine)

  1. Copy the example project into the sandbox (as dev): 
    tar -C examples -c electron-hello | docker exec -i -u dev tesseract-sandbox-1 tar -C /workspace/projects -x
    For your own repos use Add in the app's Projects section (name, git URL, optional branch).
  2. App → Agents → Projects → electron-hello → Build → Windows installer (electron-windows, Debug). The artifact electron-hello-windows-debug-1.0.0.exe appears under Artifacts.
  3. Build Linux AppImage (electron-linux) the same way.
  4. Scripts → start with Show on display → Run, then open Display: you see and control the Electron window from the phone.
npm 11 skips untrusted install scripts. If a process log says "Electron failed to install correctly", run npm install-scripts approve electron && npm rebuild electron in a terminal inside the project. Windows installers are verified as files; running Windows Electron builds under wine is best-effort (Electron 44 does not render under wine 10) — smoke-test the Linux build on the display instead. macOS builds are not possible in the sandbox.

9. Claude Code inside the sandbox

  • Open a Claude terminal from the app (or bun run sandbox shell then claude) and log in once. Credentials live in the tesseract-home volume.
  • SPEC.md is installed as /home/dev/.claude/CLAUDE.md on first start, so Claude follows the sandbox operating rules.
  • Headless runs from the phone (Claude quick action) stream their output to the app; they use TESSERACT_CLAUDE_PERMISSION_MODE.
  • Inside the sandbox, the agent calls the controller with tesseract-controller api <METHOD> <PATH> [JSON|-] and reports status with tesseract-controller emit --status building --message "…".

bun run sandbox up --mode host-tailscale

Native VNC clients (e.g. on a laptop in the tailnet) can connect to port 5901 with the VNC password.

Developing the monorepo

bun install
bun run typecheck          # protocol, client, controller (+ ui), mobile
bun run test               # all workspace unit tests
bun run lint

# Controller on your machine (loopback, temp workspace)
TESSERACT_HOST=127.0.0.1 TESSERACT_WORKSPACE=/tmp/tesseract-ws bun run controller:dev
bun run controller:build   # single binary: apps/controller/dist/tesseract-controller

# Mobile
bun run mobile

Rules for contributors: CODING.md (no unnecessary comments, no constants in UI files, reusable components, logic in hooks). The wire contract lives in docs/architecture/00-blueprint.md and packages/protocol — change them together with the code.

Adding dependencies: run bun add <pkg> inside the package directory; for Expo native modules use bunx expo install <pkg> in apps/mobile (then rebuild the dev client).

Security notes

  • The sandbox is the development machine; the host only runs Docker. No privileged containers, no host bind mounts (except the read-only Tailscale serve config), minimal capabilities, resource limits.
  • Default mode publishes nothing on host interfaces; access is tailnet-only, plus a bearer token and one-time 60-second tickets for sockets and downloads.
  • The pairing token = full control of the sandbox. Treat the QR code like a password; rotate it if leaked.
  • Anything running as dev inside the sandbox (builds, Claude, terminals) can read the token — the container is the security boundary, not the user account.
  • --dind runs a privileged sidecar: a compromised sandbox can then reach host root. Only enable it when you need Docker inside.
  • Headless Claude runs default to bypassPermissions inside the container; set TESSERACT_CLAUDE_PERMISSION_MODE to restrict.

Full threat model: docs/architecture/security-model.md.
